# 0001. Selenide + JUnit 5 для UI-автотестов

Дата: 2026-09-21
Статус: принято

## Context

Нужен стек UI-автотестов для учебного репозитория: минимум
шаблонного кода, тесты читаются как сценарии, запуск одинаковый
локально и в CI.

Альтернативы:

- Чистый Selenium — требует ручных ожиданий (`WebDriverWait`),
  управления драйвером и кода для скриншотов: тест тонет
  в инфраструктуре.
- TestNG — рабочий раннер, но JUnit 5 — стандартная платформа
  в связке с Gradle (`useJUnitPlatform`), экосистема шире.

## Decision

Java 21 + Gradle, раннер — JUnit 5 (junit-jupiter), браузер —
Selenide поверх Selenium:

- авто-ожидания: `shouldHave`, `click`, `setValue` сами ждут
  элемент до таймаута, `Thread.sleep` не нужен;
- короткий DSL: `open`, `$`, `shouldHave` — тест читается
  как требование;
- скриншоты при падении — лисенер `allure-selenide`, подключён
  один раз в `TestBase` (см. ADR-0002).

Версии — в `build.gradle`, общая настройка — в `TestBase`,
устройство тестов — `docs/kb/selenide.md`.

## Consequences

Тесты короче и не содержат инфраструктурного шума; драйвер
скачивает Selenium Manager. Цена — зависимость от Selenide:
магия ожиданий скрыта, про таймаут нужно помнить. Возможности
TestNG (группы, xml-сьюты) недоступны — проекту они не нужны.
