# Домашнее задание

Финальная фаза: пройти полный цикл «продукт → тесты → meta-слой → PR»
самостоятельно — так, как это делали фазы 1–7.

## Задание

1. Добавь автотесты на неуспешную авторизацию — без доработки
   продукта:
   - неверная пара логин/пароль → сообщение об ошибке;
   - не введён логин и/или пароль → форма показывает ошибку;
   - сначала напиши тесты вручную;
   - затем добавь их с помощью агента и отладь стабильную
     генерацию без галлюцинаций;
   - в ходе добавления и отладки генерации обнови harness —
     rules/skills в `.devin/`, чтобы агент генерировал тесты
     правильно с первого раза.
2. Доработай продукт — `index.html`:
   - чекбокс «Запомнить меня» на форме логина;
   - больше обработок ошибок: раздельные сообщения для пустого
     `username`, пустого `password` и обоих пустых полей;
     вход при этом не считается выполненным.
3. Напиши автотесты на новое поведение (в помощь — skill `add-ui-test`):
   - своё сообщение при пустом имени пользователя;
   - своё сообщение при пустом пароле;
   - сообщение при двух пустых полях;
   - чекбокс «Запомнить меня» (проверь, что он существует и кликабелен);
   - сценарий успешного входа и тесты из п. 1 остаются зелёными.

## Ключевое условие

ДЗ не принимается, если изменён только код. Meta-слой обязан догнать
продукт:

- новый ADR по `docs/adr/0000-template.md` — что добавлено и почему
  решили именно так (skill `write-adr`);
- `docs/kb/` и `INDEX.md` — обнови, если твои изменения затронули
  покрытые там темы;
- при необходимости — поправь skill или rule в `.devin/`.

Зачем это нужно: harness живёт, только если его поддерживают вместе
с кодом. Rules, kb и ADR, которые устарели, — хуже отсутствия
документов: агент им доверяет и получает врущие инструкции. Зелёные
тесты говорят «код работает», но ничего не говорят о том, что
инструкции всё ещё соответствуют реальности.

## Критерии приёмки

- `./gradlew test` зелёный локально.
- CI на PR зелёный.
- Создан новый ADR.
- `docs/kb/` обновлена (или в PR обосновано, почему обновление не
  понадобилось).
- `AGENTS.md` ≤ 50 строк.
- PR оформлен по форме — три обязательных раздела:
  `## Что это такое`, `## Что сделано`, `## Как проверить`.

## Чек-лист самопроверки

Пройди перед сдачей:

- [ ] Тесты на неуспешную авторизацию добавлены и зелёные:
      неверные креды, пустой логин, пустой пароль.
- [ ] Harness обновлён по итогам отладки: агент генерирует тест
      без галлюцинаций.
- [ ] Чекбокс «Запомнить меня» есть на форме и работает.
- [ ] Пустой `username` → своё сообщение об ошибке.
- [ ] Пустой `password` → своё сообщение об ошибке.
- [ ] Оба поля пустые → сообщение об ошибке, вход не выполнен.
- [ ] Новые тесты по конвенциям проекта: наследуются от `TestBase`,
      Selenide-стиль, `@DisplayName` на русском, один тест — один сценарий.
- [ ] `./gradlew test` зелёный локально.
- [ ] CI на PR зелёный.
- [ ] ADR создан по шаблону: номер, дата, статус,
      Context / Decision / Consequences, ≤ 60 строк.
- [ ] `docs/kb/INDEX.md` указывает на актуальные файлы.
- [ ] `AGENTS.md` ≤ 50 строк, карта ведёт на реальные файлы.
- [ ] В PR три обязательных раздела, все ссылки на файлы реальны.
- [ ] В PR нет лишних файлов: только продукт, тесты и meta-слой.
